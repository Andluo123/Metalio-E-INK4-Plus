# 自动测试录音回放排查

设置中的录音测试走本地链路：I2S 麦克风 → 16 kHz PCM → 取左声道 → Opus → 测试队列 → Opus 解码 → 输出重采样 → I2S → PA/喇叭。不经过网络发送，也不经过 AFE 降噪。

串口保留一次正常和一次异常测试从 `audio-test begin` 到 `playback finished` 的完整日志，另保留 `BTAudioCodec`、`MetalioAudio`、`AudioCodec` 错误。每次按住约 5 秒，先保持安静，再说话或拍手，松开听回放。

- `begin`：输入/输出采样率、通道、参考输入、增益和音量。
- `capture-mic` / `capture-reference`：读取并重采样后的左右声道。当前测试取左声道作为麦克风。
- `encode-input` / `encoded`：进入编码的 PCM、生成的 Opus 字节数及去向。`playback-tail` 表示停止录音时尚未完成的编码尾帧已接到播放队列。
- `decoded` / `output`：解码后及输出重采样后的 PCM。相同 `frame` 可用于比对编码、解码、输出。Opus 是有损编码，幅度不会完全一致。
- `stop`：已入队帧数、已生成包数、待编码队列及网络发送队列长度；待编码队列可能还存在一帧正在编码，发送队列长度不代表本次测试发送了网络音频。

PCM 指标：`rms` 为有效幅度，`dc` 为均值，`peak` 为峰值，`clip` 为接近满量程的采样数，`zero` 为零值数，`crossings` 为过零次数。首帧和每 16 帧记录一次，无录音内容转储。

定位方法：

1. 若说话/拍手时 `capture-mic` 幅度无变化，或持续大量削顶，优先检查麦克风、蓝牙模块工作模式、I2S 时钟/槽位/有效位格式。若只有参考声道随环境音变化，检查左右声道映射。当前 BTAudioCodec 使用 32 位立体声输入，右移 12 位后限幅为 16 位；需要结合模块实际格式验证，不能凭噪声直接调整位移。
2. 采集和编码前正常，解码后异常，检查 Opus 编解码状态、包参数和错误日志。
3. 解码正常、输出 PCM 异常，检查重采样；输出 PCM 正常但听到沙沙声，检查 I2S 输出格式、模块模式、PA 和喇叭。
4. `Input short read` 表示采集不足整帧，已丢弃该帧；`Output short write` 表示输出未完整写入。测试采集失败会重试并记错，不再直接退出输入任务。

仅有幅度统计不能证明音频内容正确，也不能替代设备复现。本日志用于缩小故障阶段。
